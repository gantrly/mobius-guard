# Results: the proxy's request check (2026-10-29)

Part 3e of the roadmap: the proxy's normalisation and rules (decision 0010), measured with the
same suite, thresholds and rules as the baselines in
[2026-10-27-baselines.md](2026-10-27-baselines.md). Nothing here was tuned on these sets:
the rules were written before this run and are reported as they were.

Detectors added to the comparison:

- **mobiusguard-rules**: the proxy's normalisation + named rules, on CPU. Its default policy
  blocks only on a high-severity rule.
- **piguard-norm / protectai-v2-norm**: the same pretrained models, each text scored on
  every view the proxy makes (original, normalised, decoded base64), highest score kept.
  This isolates what normalisation alone does for an existing classifier.

Suite `ids_sha256 6db51432…`, thresholds from 16,286 ordinary oasst1 messages, GPU scoring on
an NVIDIA L4, latency on an AMD EPYC 7R13 with 4 threads. **†** = trained on that set.

## Normalisation makes existing classifiers see through obfuscation

Recall at 1% false positives on ordinary messages (%):

| Attack family | n | ProtectAI v2 | **+ normalisation** | PIGuard | **+ normalisation** |
|---|---:|---:|---:|---:|---:|
| obfuscated: spaced letters | 1,000 | 0.0 | **38.2** | 0.8 | **61.0** |
| obfuscated: look-alike letters | 1,000 | 16.6 | **40.7** | 4.1 | **60.7** |
| obfuscated: invisible characters | 1,000 | 11.2 | **41.4** | 0.2 | **60.5** |
| obfuscated: base64 | 1,000 | 45.5 | **79.1** | 100.0 | 100.0 |
| obfuscated: leetspeak | 1,000 | 0.3 | **37.1** | 97.1 | 98.2 |
| Gandalf (plain) | 999 | 90.9 | 90.9 | 91.7 | 91.7 |
| LLMail-Inject (plain) | 2,981 | 2.1 | 2.1 | 28.3 | 28.6 |

False positives at the same threshold did not move: oasst1 0.9% → 0.9% and 1.0% → 1.0%;
NotInject 4.7 → 5.0 and 8.3 → 8.3; OR-Bench 0.8 → 0.7 and 11.1 → 10.6.

Another way to see it: of the plain attacks each model catches, how many it still catches
after obfuscation (at 1% false positives):

| Trick | ProtectAI v2 | + normalisation | PIGuard | + normalisation |
|---|---:|---:|---:|---:|
| spaced letters | 0 / 381 | **382 / 382** | 6 / 612 | **608 / 612** |
| look-alike letters | 137 / 381 | **382 / 382** | 40 / 612 | **607 / 612** |
| invisible characters | 78 / 381 | **382 / 382** | 2 / 612 | **605 / 612** |

Normalisation recovers essentially everything the models could already catch. The
remaining gap (about 61% rather than about 92% on obfuscated copies) is attacks the models
miss even in plain text: obfuscated copies are drawn from every attack source, including
LLMail and SPML, which PIGuard finds hard to begin with.

## The proxy's rules: precise, not broad

The default policy blocks only on a high-severity rule:

| | blocked |
|---|---:|
| **Benign texts, all 8 sets (23,221)** | **0** |
| Gandalf | 35.7% |
| SPML | 12.1% |
| obfuscated copies (each family) | 11.3–22.5% |
| LLMail-Inject | 8.6% |
| jackhhao jailbreaks | 6.2% |
| BIPIA | 0.0% |

Counting medium-severity hits as well (the "mobiusguard-rules" column of the report, at a
threshold that flags 0.0% of ordinary messages): Gandalf 37.9%, LLMail 31.6%, jackhhao
33.4%, obfuscated copies 18–100%, with false positives of 0.0–2.1% on the benign sets.

Rules are the first, cheap layer: no false blocks, and they keep working on obfuscated text.
They are not the detector; broad recall needs a classifier, ours in v0.2.

## Cost

CPU latency per text, batch 1, P50 (ms):

| Detector | 64 tokens | 256 tokens | 512 tokens |
|---|---:|---:|---:|
| mobiusguard-rules (normalisation + rules) | 0.12 | 0.45 | 0.90 |
| PIGuard | 213 | 480 | 1,151 |
| PIGuard + normalisation | 210 | 479 | 1,221 |

Normalisation adds under a millisecond; the classifier extra costs a second per long prompt
on a CPU, which is what the v0.2 classifier targets.

## What it shows for v0.2

1. Normalise before any detector: it closes the obfuscation gap without new false positives.
2. The rules are a safe default block layer (zero false blocks on 23,221 benign texts).
3. Adaptive and indirect attacks (LLMail, BIPIA) remain the hard part for every detector,
   and the reason to train our own classifier.
