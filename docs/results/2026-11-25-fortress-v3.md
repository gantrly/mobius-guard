# Results: Fortress v3, full run against v1 (2026-11-24)

The full run after the test runs in
[2026-11-24-fortress-v2-diagnosis.md](2026-11-24-fortress-v2-diagnosis.md), using recipe D of
[decision 0017](../decisions/0017-disguises-carry-no-label.md):

- the v2 data without the tool-call sources;
- disguised copies of both labels, with look-alike letters held out;
- the developer group weighted at 0.598.

**Not released yet**: the release is the maintainer's decision.

**Setup:**
- **Data:** 222,575 train and 24,675 validation items (`runs/train-v3D`).
- **Model:** DeBERTa-v3-xsmall at 5e-5, seed 0, 3 epochs (one seed: decision 0017).
- **Hardware and versions:** NVIDIA L4, torch 2.15.0, transformers 5.22.1.
- **Code:** training ran at commit `fb2dbac`; scoring and the gate at `1551d2a`.
- **Time:** training 1 h 41 min, every stage on its first try.
- **Scoring:** suite v0.2 plus the extended harmless sets (`extend-suite`). Both models are
  scored as the proxy runs them (every view, highest score) at their own 1% thresholds, set
  on oasst1's calibration half.

## Against v1

The gate passes **36 of 40** checks.

| Spaced / leetspeak / invisible attacks caught (plain originals 52.5%) | 99.6 / 92.7 / 69.8% | 54.3 / 55.0 / 58.9% |
| Developer check, INT8 at its own threshold (of 8 blocked) | 5 | 3 |

| Harmful: OR-Bench toxic / XSTest unsafe caught | 90.4 / 84.0% | 90.5 / 83.5% |
| Harmful: OR-Bench hard (sounds harmful, is not) blocked | 48.2% | 51.0% |

**The four failed checks:**

- **Developer check:** 2 of 8 blocked, as the proxy runs it. The rule is at most 1.
- **Look-alike letters, caught minus harmless blocked:** 53.5% against 61.4%, with a slack
  of 3 points.
- **jackhhao harmless prompts:** 3.2% blocked, against a bar of 2.0%.
- **Harmful output, OR-Bench hard:** 51.0% blocked, against a bar of 50.9%.

**Reading the results.**

- **Look-alike letters.** v3 catches 56.9% of these attacks, above the 52.5% it catches on
  the same attacks in plain text, so it reads through them. v1's 66.8% is above its
  plain-text rate too (53.3%). That is the same kind of shortcut as its spaced-letter score,
  so this check compares v3 with an inflated baseline.
- **LLMail.** The test runs suggested 50%, but the full run landed at v1's rate. The
  single-seed, 1-epoch numbers for LLMail were noise.
- **The marginal failures.** jackhhao and OR-Bench fail by small margins. The developer
  check improved (from 5 of 8 to 3), but three messages remain: the two "Call save_note…"
  requests and "my key is …". A classifier that cannot tell a user's request from a
  document cannot pass them.
